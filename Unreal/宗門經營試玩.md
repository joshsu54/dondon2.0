# 凌雲重建：宗門經營第一版

此版延續原本的修仙世界，主軸是**經營宗門與招募弟子**。地圖最初為 `TownLayout_10`，由 09 另存；小鎮、山路、客棧與舊版關卡保留。目前預設為 `TownLayout_13`：同一套經營玩法，加上 12 的弟子工作與尋路，玩家換成 Q 版角色。

## 開始遊玩

在 UE 5.8 開啟 `XiuXianTown/XiuXianTown.uproject`，選擇 `/Game/Maps/TownLayout_13`（預設，Q 版玩家；10–12 仍可選），按 Play。Windows 已編譯的本機也可執行專案根目錄的 `開始遊玩.ps1`，直接啟動遊戲模式；尚非獨立打包版本。

| 操作 | 功能 |
| --- | --- |
| WASD／滑鼠／空白 | 移動、轉向、跳躍 |
| E | 採集、接取／交付委託、招募、建設、與弟子談話 |
| J | 開關宗門簿，查看弟子、產出與地點提示 |
| 宗門簿開啟時按 1、2、3 | 輪換對應弟子的工作，只會選擇已開放的工作 |
| F5 | 手動存檔；重要操作與每 30 秒也會自動存檔 |

青玉光柱與 HUD 距離指向下一個主要目標。南側營地的英文標牌是場景定位輔助，中文操作說明顯示在 HUD。

## 第一輪流程

1. 向北走到小鎮委託牌，接取採藥委託。
2. 沿登山路採三株靈草，返回委託牌領取 10 靈石。
3. 返回小鎮南方，沿青石步道進入重建營地，免費邀請石砥入門。
4. 用初始木石修復藥圃，石砥會自動開始照料。保持至少一位弟子種植，供應糧食。
5. 在營地採竹木、石料與野果；每處採集後 6 秒恢復。玩家採集不消耗糧食，因此缺糧時仍能恢復生產。
6. 興建弟子舍，邀請林溪；把一位弟子安排採集木石。
7. 在北端委託牌重複交付建材賺取靈石，興建靜修臺，再邀請岳青並分派修煉。
8. 達到 3 位弟子、3 座設施、聲望 30、靈石 15，向營地北側的雲不鶴申請晉升二品。之後仍可繼續經營。

## 世界配置

北方是山門、採藥步道與休憩亭；中央是既有小鎮、客棧與委託牌；南方是新加入的宗門重建營地。營地中央保留可步行的主路，東側為藥圃與靜修臺，西側為弟子舍。竹木、採石和野果位於營地周圍。

石砥與雲不鶴沿用既有劇本；林溪、岳青是這版用於測試招募與分工的暫定弟子，未改寫既有第一章主線。

## 經營數值

初始庫存：木材 8、石料 6、糧食 6。初始床位 1，弟子舍完成後為 4；本版提供 3 位弟子。

| 項目 | 花費 | 效果 |
| --- | --- | --- |
| 石砥入門 | 免費，需先完成採藥 | 第一位弟子，聲望 +3 |
| 林溪入門 | 靈石 5、糧食 2 | 第二位弟子，聲望 +3 |
| 岳青入門 | 靈石 8、糧食 3 | 第三位弟子，聲望 +3 |
| 藥圃 | 木 6、石 4 | 開放種植；聲望 +5 |
| 弟子舍 | 木 12、石 8、靈石 6 | 床位變為 4；聲望 +5 |
| 靜修臺 | 木 8、石 6、靈石 8 | 開放修煉；聲望 +5 |
| 建材委託 | 木 4、石 2 | 靈石 +6、聲望 +2，可重複 |
| 宗門晉升 | 靈石 15，並符合規模條件 | 宗門升為二品，只扣款一次 |

每 20 秒生產一輪，每位工作弟子消耗 1 糧食。藥圃先結算，方便糧食供應其他工作。

| 工作 | 每輪產出 |
| --- | --- |
| 採集木石 | 木材 +4、石料 +3 |
| 照料藥圃 | 糧食 +4（扣除自己的餐食後淨增 3） |
| 修煉傳道 | 聲望 +3 |

庫存上限為各 999。沒有糧食時弟子暫停工作，不會死亡。離線不計時、不消耗糧食，也不產出資源。

## 存檔與目前範圍

進度位於 `XiuXianTown/Saved/SaveGames/Dondon_SectManagement_v1.sav`。保存採藥進度、庫存、弟子工作、建築、宗門等級與生產計時；再次遊玩從原本安全出生點出發。讀取失敗時保留原存檔，不用初始進度覆蓋。測試另用 `Management10_Test_*` 存檔。

這是可擴充的經營原型：NPC 暫用簡化人形，弟子尚不會尋路走到工作場所；弟子舍是場景方塊雛形，建成的設施以外觀與互動點表示，未做室內碰撞。尚未加入自由擺放建築、個性／資質、裝備、戰鬥、完整第一章過場、音效與正式打包。

## 開發與驗證

新增程式在 `XiuXianTown/Source/XiuXianTown/SectAdventure.*`。舊任務導演僅增加子類別擴充入口與經營 HUD 版面方法，舊關卡仍使用原本導演。

- `Tools/build_management10.py`：從 09 建立新 10；拒絕覆寫既有 10。
- `Tools/test_management10.py`：真實 PIE 功能測試，以反射呼叫互動，功能檢查間會傳送；另有營地中央道路的連續行走及第二次 PIE 存檔重開檢查。
- `Tools/run_management10.ps1 -Task Test`：背景啟動測試，每次使用獨立測試存檔。
- 實際結果以 `management10_build.json`、`management10_runtime.json` 與畫面檢查紀錄為準，不能把 API 驅動測試稱為實體鍵鼠全流程驗收。

Windows 編譯若因中文路徑產生 MSVC PCH 錯誤，需透過純英文路徑的目錄別名編譯，並重新產生 Intermediate 快取。原始模型庫部分檔案是匯入來源就存在的 Git LFS 指標；本輪場景只重用 Unreal 中已匯入的實體資產。
